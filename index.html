Module 02 — Most Important

Resolution Calculator

Tells you the minimum number of camera pixels required to detect or measure your target defect.

📷 What is Resolution in Machine Vision?
Resolution = how many pixels the camera has. But what matters is not just how many pixels — it's how many pixels land on your defect.

Imagine your FOV (Field of View) is a window of 150mm × 100mm. If your camera has 1500 × 1000 pixels, then each pixel covers exactly 0.1mm of real-world space. That 0.1mm is your Pixel Size on Object.

If your smallest defect is 0.5mm, and each pixel covers 0.1mm, then that defect covers 5 pixels. That's your Pixels Per Defect (PPD). You need at least 3 PPD to detect something — more for measurement.
Detection
3–5 PPD
Pass/fail only. Can you see it? Yes or No.
Inspection
5–10 PPD
Classify defect type, rough size
Measurement
10–20 PPD
Measure dimensions accurately
High Precision
20–30 PPD
Sub-pixel accuracy, metrology
Formulae
Required Pixels X (Nx) = (FOV_x ÷ Defect Size) × PPD
Required Pixels Y (Ny) = (FOV_y ÷ Defect Size) × PPD
Pixel Size on Object = FOV ÷ Camera Pixels → mm/px → ×1000 = µm/px
Measurement Accuracy ≈ Pixel Size ÷ 10 (with sub-pixel interpolation algorithms)

Module 05 — Conveyor Applications

Motion Blur & FPS Calculator

Calculate minimum required frame rate, maximum allowable exposure time, and motion blur — based on conveyor speed, FOV, and pixel geometry. All unit conversions automatic.

📷 How is FPS actually calculated?
FPS is determined by how fast the object moves relative to the FOV height (the dimension in the direction of travel) and how much image overlap you want between consecutive frames.

FPS = Speed (mm/s) × (1 − Overlap) ÷ FOV Height (mm)

With 0% overlap the camera fires exactly once per FOV length — the minimum rate to guarantee no gap. With 20% overlap each frame shares 20% of its area with the next, giving redundancy. With 100% overlap every single pixel row is captured by two frames — this equals the line rate mode.

Motion Blur = Speed × Exposure Time. To keep blur below 1 pixel width, exposure must be shorter than Pixel Size ÷ Speed.

0% overlap
Minimum
No gap, no redundancy. Trigger on FOV boundary.
20–30% overlap
Recommended
Handles timing jitter, ensures full coverage.
Blur Rule
< 1 pixel
Blur (µm) must be less than pixel size on object (µm).
Formulae
Min FPS (no overlap) = Speed (mm/s) ÷ FOV Height (mm)
FPS with overlap = Speed (mm/s) ÷ (FOV Height × (1 − overlap%))
Max Exposure = Pixel Size on Object (mm) ÷ Speed (mm/s) → µs
Motion Blur = Speed (mm/s) × Exposure Time (s) → µm
Blur Ratio = Motion Blur ÷ Pixel Size on Object → must be < 1.0

Module 08 — Illumination Spectral

Color Contrast Selector

Choose the right illumination color to maximize contrast between your object and its background.

🎨 What is Color Contrast in Machine Vision?
A camera sees in grayscale (or color). Contrast is the difference in brightness between the defect and the surrounding area. The higher the contrast, the easier it is for the vision algorithm to detect the defect reliably.

How lighting color affects contrast: Objects absorb or reflect specific wavelengths (colors) of light. A red apple illuminated with red light appears very bright — it reflects the same color. The same red apple under blue light appears very dark — it absorbs blue wavelengths. This dark appearance = high contrast against a lighter background.

Rule 1 — Brighten the object: Use light the same color as the object → it reflects fully → appears very bright in camera.
Rule 2 — Maximize contrast: Use light the opposite color of the object → it absorbs → appears very dark → maximum contrast vs background.

How to use this module: Select your object color and background color below. The tool will recommend the best illumination color for both brightness and contrast goals, with the reason explained.

Module 11 — Hardware Reference

Sensor Size Converter

Camera datasheets give sensor size in the old "optical format" like 1/2.9", 1/1.8", 2/3". This converts those to actual physical dimensions (mm) and aspect ratios.

📐 Why is 1/2" not actually 12.7mm wide?
The optical format notation (1/2", 2/3", 1") comes from old vacuum tube camera technology and is not the actual diagonal size. The "1-inch" format is actually ~16mm diagonal, not 25.4mm. This is a historical convention that manufacturers still use today.

The actual sensor dimensions are calculated from the optical format using a fixed conversion factor. The sensor is typically 4:3 or 16:9 aspect ratio within that format.

Module 12 — Wide-Coverage Systems

Multi-Camera Array Calculator

When the required FOV is wider than a single camera + lens combination can cover at the needed resolution, split coverage across multiple cameras. Calculates how many cameras you need, the per-camera FOV with overlap, and resulting per-camera lens spec.

🎥 When do you need multiple cameras?
A single camera has a fixed resolution (megapixels). As target FOV gets wider, the pixel size on object grows — eventually your smallest defect can no longer be resolved by enough pixels (PPD too low). At that point, instead of accepting poor resolution, split the wide FOV into N overlapping strips, each covered by its own camera + lens, all at the same working distance. Each camera now only has to resolve its own narrower strip, so resolution per camera improves.

Overlap between adjacent camera FOVs (typically 5–15%) ensures no inspection gap at the stitch line due to lens distortion, mounting tolerance, or mechanical vibration.

Formulae
Cameras needed N = ceil( Total FOV Width ÷ (Max FOV per camera × (1 − overlap%)) )
Per-camera FOV Width = (Total FOV Width ÷ N) × (1 + overlap%)
Per-camera Focal Length = (Sensor Width × Working Distance) ÷ Per-camera FOV Width
Total resolution = N × per-camera resolution (parallel acquisition, not summed pixels in one frame)

Module 15 — Hardware Reference

Lens ↔ Sensor Compatibility

A lens only works with a sensor if its image circle is at least as large as the sensor diagonal. Pick a sensor to see which lens formats cover it, or pick a lens to see which sensors it can be used with.

📐 The rule
Lens format ≥ sensor format → works. A 2/3" lens on a 1/1.8" sensor is fine: the sensor just uses the centre of the image circle (sharper corners, less distortion). The FOV is set by the sensor size and focal length, not by the lens format.
Lens format < sensor format → vignetting. A 1/2" lens on a 2/3" sensor gives dark or blurry corners, because the image circle doesn't reach them.
Also check the mount (C / CS / M12 / M42 / F) and that the lens resolves the pixel size (MP rating).

A telecentric lens has a fixed magnification, so the field of view comes straight from the sensor: FOV = pixel size × resolution ÷ magnification. Enter the magnification to get the FOV, or the FOV you need to get the magnification, then check that the lens covers your sensor.

Formulae
FOV = pixel size × pixels ÷ magnification (same as sensor size ÷ magnification)
Object resolution = pixel size ÷ magnification per pixel
Approx. DOF ≈ 2 × working F/# × CoC ÷ magnification², CoC = 2 px
